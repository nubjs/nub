# Raw measurement log — Windows build jail via restricted token + low integrity.
# Appended as each fact lands. Machine: disposable GCE nub-win-rtok,
# Windows Server 2025 (windows-2025 image family), e2-standard-4 x86_64.
#
# SETUP FACTS (cost time; recorded so the next run does not repeat them):
# - MEASURED: the GCE guest agent does NOT wire Windows SSH on windows-2025.
#   Serial log: 'Could not determine if openssh version is compatible: could not
#   find version: service image path "SYSTEM\CurrentControlSet\Services\sshd"'.
#   enable-windows-ssh=TRUE is not sufficient; a windows-startup-script-ps1 must
#   start sshd and place authorized_keys itself.
# - MEASURED: `powershell -Command -` over SSH silently produced NO output for a
#   script containing Start-Process -Credential. scp the file + `powershell -File`
#   is reliable. Use that.
# - MEASURED: appending SyslogFacility/LogLevel to the END of the Windows
#   sshd_config lands them INSIDE the trailing `Match Group administrators` block,
#   which is invalid -> sshd fails to start -> you are locked out. Insert before
#   the first Match line.

  il=low   -> "Mandatory Label\Low Mandatory Level  S-1-16-4096"
  il=medium-> "Mandatory Label\Medium Mandatory Level S-1-16-8192"

*** SSH/session-0 LIMITATION DOES NOT APPLY. *** AppContainer returns
0xC0000142 over SSH because a LowBox token cannot attach the services-session
window station. A restricted + LOW-IL child LAUNCHED FINE over SSH with the
INHERITED station (Service-0x0-7958e$). Untrusted IL launched too. So this
mechanism is fully measurable over SSH -- no ci-adhoc-test workflow needed.
Optional (unnecessary) belt-and-braces that also works: CreateDesktopW + a
low-IL label on the new desktop; needs WRITE_OWNER in the CreateDesktopW access
mask (0x1FF alone -> SetUserObjectSecurity ERROR_ACCESS_DENIED=5).

HARNESS BUG CAUGHT BY THE BASELINE (recording per discipline): all six arms
first failed identically with `CreateFileW(NUL) err=2`, which reads exactly like
"mechanism unavailable". The --il none BASELINE failing too localized it to the
harness: the CreateFileW P/Invoke lacked CharSet=CharSet.Unicode, so the ANSI
default marshalled the name into a UTF-16 API. Without the baseline arm this
would have been reported as a launch failure.

  policy 1 = SYSTEM_MANDATORY_LABEL_NO_WRITE_UP

NEGATIVE CONTROL (this is what makes the positive result mean something):
  label C:\        -> ERR=5 ACCESS_DENIED
  label C:\Windows -> ERR=5 ACCESS_DENIED
=> the capability is owner/DACL-derived, NOT a blanket privilege. An unprivileged
   process can only relabel what it already owns, which is exactly the grant
   scope we want and no more.

COST: recursive relabel of the project tree = 11 entries, errors=0, 77 ms.

END-TO-END DIFFERENTIAL, low-IL child, native cmd.exe redirection:
  write into relabeled project dir   -> WROTE_PROJ
  write into %USERPROFILE%           -> "Access is denied." DENIED_PROFILE
  write into C:\                     -> "Access is denied." DENIED_C
=> the write allowlist is real: granted where labeled, refused everywhere else,
   with the process still able to READ everything.

THE ONE REAL COMPAT BREAK, ITS CAUSE, AND ITS REMEDY (MEASURED)
================================================================
With a COLD prebuild cache, `prebuild-install` FAILS at low IL:
  prebuild-install warn install ENOENT: no such file or directory, open
  'C:\Users\probe2\AppData\Roaming\npm-cache\_prebuilds\bc594a-sqlite3-v6.0.1-
   napi-v6-win32-x64.tar.gz.<pid>-<rand>.tmp'
It stages the download into %APPDATA%\npm-cache\_prebuilds, which is
Medium-labeled, so the low-IL process cannot create/write it.

THREE-ARM DIFFERENTIAL, one variable changed per arm, trees + cache reset between:
  ARM 1  cold cache, il=none                 sqlite3 rc=0 1,980,416 B | keytar rc=0 707,584 B
  ARM 2  cold cache, il=low, cache NOT granted  sqlite3 rc=1 absent   | keytar rc=1 absent
  ARM 3  cold cache, il=low, cache GRANTED (labeled low)
                                             sqlite3 rc=0 1,980,416 B | keytar rc=0 707,584 B
=> ARM 1 rules out "the cold cache is the problem". ARM 2 attributes the break to
   the jail. ARM 3 proves granting the cache dir is a COMPLETE remedy -- artifact
   sizes byte-identical to ARM 1.
=> Because the cache was cold, ARM 3's bytes came over the wire from github.com
   INSIDE the low-IL jail. That is real-package HTTPS under the jail, confirmed
   by byte count, not by exit code.

REQUIRED WRITE GRANTS (each measured, not guessed):
  1. the package dir / project root (recursive relabel; 77 ms for 11 entries,
     3,878 entries for the largest fixture, errors=0)
  2. %TEMP%  -- else node-gyp/npm/tarball extraction die (measured EPERM)
  3. the PM cache dir that lifecycle scripts inherit via npm_config_cache
     -- else prebuild-install/node-pre-gyp die on a cold cache (measured above)
  4. HKCU is NOT writable at low IL (measured). Narrow exposure: postinstalls
     that write registry keys. No file-label remedy; would need a registry
     label, which is the same API on a different object type.
