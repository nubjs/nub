---
title: Using Nub with Turborepo
description: Run Turborepo on top of Nub in a monorepo, keeping your package manager field and lockfile, with TypeScript and env files working inside every task.
---

Turborepo schedules and caches tasks across your packages; Nub installs dependencies, provisions Node, and augments the Node each task runs. You keep your Turborepo setup and launch it through Nub.

## Setup

Keep the `packageManager` field and lockfile as they are, install with Nub, and run Turborepo through Nub:

```bash
nub install            # instead of pnpm install; same lockfile
nub run build          # a root script: "turbo run build"
nubx turbo run build   # or run turbo directly through nubx
```

Turborepo detects the package manager from `packageManager` and the lockfile, and it has no setting that names Nub. None is needed: Nub round-trips the npm, pnpm, and bun lockfiles and reads yarn's, so Turborepo keeps seeing the package manager it knows.

## TypeScript inside tasks

For each package that defines a task, Turborepo spawns the package manager, such as `pnpm run build`, and that process inherits Turborepo's environment. When Turborepo runs under Nub, that environment carries Nub's augmentation, a `NODE_OPTIONS` preload and a `node` shim on the `PATH`. So the `node` a task's script invokes is Nub's augmented Node.

A build script of plain `node ./build.ts` then runs TypeScript directly and loads that package's `.env`, with no per-package configuration:

```jsonc
// packages/lib/package.json
{
  "name": "@acme/lib",
  "scripts": { "build": "node ./build.ts" }
}
```

```jsonc
// turbo.json
{
  "tasks": { "build": {} }
}
```

```bash
nub run build         # root script: "turbo run build"
```

```
@acme/lib:build: cache miss, executing
@acme/lib:build: [lib] built ok
 Tasks:    1 successful, 1 total
```

<Callout type="warn" title="Launch Turborepo through Nub">
A `turbo run` started from a plain shell runs tasks on the `node` on your `PATH` with no augmentation, and a `.ts` entry fails to parse. Keep the entry point a `nub run` script or `nubx turbo` so every run goes through Nub.
</Callout>

## Node version

Nub provisions the Node your project pins, so every task in the monorepo runs on the same version without nvm or Corepack. Pin it with `.node-version`, `.nvmrc`, `devEngines.runtime`, or `nub node pin`. The package manager Turborepo spawns runs on that Node too, not an older one it finds on the `PATH`.

## Caching and env files

Turborepo owns the task graph, scheduling, and caching. Nub owns the runtime, installs, and env loading under each task.

- **Cache keys** — Turborepo passes `NODE_OPTIONS` through to tasks without hashing it, so adopting Nub does not invalidate your cache.
- **Env files** — each task loads the `.env` for the package it runs in. Turborepo's `env` and `globalEnv` still control cache hashing, so a value that must affect the cache still belongs in `turbo.json`.
