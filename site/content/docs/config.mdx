---
title: Config reference
description: The project file that configures Nub's runtime, dependency installs, and temporary package runs.
---

Put `nub.jsonc` at the project root. Nub finds the nearest file by walking up from the command's working directory.

The file uses JSON with comments and trailing commas. Unknown keys and invalid values stop the command with an error.

## Reference

Every field, with its full value set. Each has its own section below.

```jsonc title="nub.jsonc"
{
  "$schema": "https://nubjs.com/schema/latest.json",

  // ── runtime — file runs, scripts, and watch mode ──

  // relative paths or bare specifiers, loaded in order
  "preload": ["./setup.ts", "tsx/esm"],

  // any flag your Node accepts in NODE_OPTIONS
  "nodeOptions": ["--enable-source-maps"],

  // passed on the command line, so the full V8 set
  "v8Flags": ["--expose-gc"],

  "nodeCompat": false,             // true = plain Node, pinning kept

  // true = the default .env cascade | false = load nothing
  // a path, or an array of paths where later files win
  // paths expand ${VAR} and $VAR against the environment
  "envFile": [".env", ".env.local"],

  // text | jsonc | json5 | toml | yaml | ts | tsx | jsx
  "loader": { ".graphql": "text" },

  "conditions": ["development"],   // matched ahead of "default"
  "tsconfig": "./tsconfig.runtime.json",

  // warn | error | false
  // "install" and "prompt" parse for pnpm compat, behave as warn
  "verifyDeps": "warn",

  // ── installs — only when Nub is the project's package manager ──
  "install": {
    // symlink (default) | isolated | hoisted
    // "pnp" parses and is rejected at install time
    "nodeLinker": "symlink",

    "symlinkDisablePattern": ["electron"],  // symlink layout only
    "hoist": false,                // boolean | string[]; isolated only

    // <integer><s|m|h|d|w>; a bare number is rejected
    "minimumReleaseAge": "3d",
    "minimumReleaseAgeExclude": ["@company/*"],

    // for dependency build scripts, not for runs
    "nodeOptions": ["--max-old-space-size=8192"]
  }
}
```

One block is read from the global file only, because it configures your machine rather than a checkout. A project file carrying it is an error.

```jsonc title="~/.config/nub/nub.jsonc"
{
  // ...
  "dlx": {
    "consent": "prompt",       // prompt | never
    "envFile": "./tools.env"   // same forms as the top-level envFile
  }
}
```

## Global configuration

Use a project file for settings that belong to one repository, and the global file for personal defaults that apply everywhere. Both take the same fields, except that [`dlx`](#dlx) is global-only.

Nub reads these locations, nearest first:

- `nub.jsonc` in the project, found by walking up from the command's working directory
- `$XDG_CONFIG_HOME/nub/nub.jsonc` when `XDG_CONFIG_HOME` is set
- `~/.config/nub/nub.jsonc` (macOS, Linux)
- `%APPDATA%\nub\nub.jsonc` (Windows)

A project file fails loudly when it contains an invalid value. The global file is best-effort, so Nub ignores one it cannot read or parse rather than blocking every command.

## Precedence

More specific settings replace broader ones:

```text
command-line option
  ↓
environment setting
  ↓
project nub.jsonc
  ↓
global nub.jsonc
  ↓
built-in default
```

Relative paths come from the file that supplied the final value. A project `preload` path is relative to the project file; a global `preload` path is relative to the global file.

## Runtime

The top-level fields configure file runs, package scripts, and watch mode.

### `preload`

Load one or more modules before the entry file.

```jsonc title="nub.jsonc"
{
  // ...
  "preload": [
    "./instrumentation.ts",
    "./register-hooks.mjs"
  ]
}
```

Paths are resolved from the directory containing `nub.jsonc`.

```ts title="instrumentation.ts"
globalThis.performance.mark("app-start");
```

An entry may also be a bare package specifier, resolved the way an import in your project would be.

```jsonc title="nub.jsonc"
{
  // ...
  "preload": ["tsx/esm", "@company/telemetry/register"]
}
```

A bare specifier resolves through the package's `exports` map, so [`conditions`](#conditions) steers which file it loads.

```jsonc title="nub.jsonc"
{
  // ...
  "conditions": ["development"],
  "preload": ["@company/telemetry/register"]
}
```

```json title="node_modules/@company/telemetry/package.json"
{
  "exports": {
    "./register": {
      "development": "./register.dev.js",
      "default": "./register.js"
    }
  }
}
```

### `nodeOptions`

Pass Node options to runtime commands.

```jsonc title="nub.jsonc"
{
  // ...
  "nodeOptions": [
    "--enable-source-maps",
    "--stack-trace-limit=50"
  ]
}
```

### `v8Flags`

Pass V8 flags without adding them to every command.

```jsonc title="nub.jsonc"
{
  // ...
  "v8Flags": [
    "--expose-gc",
    "--stack-size=2000"
  ]
}
```

These flags reach Node on its command line rather than through `NODE_OPTIONS`, so the whole V8 flag set is available — including the flags `NODE_OPTIONS` rejects, such as `--stack-size` and `--no-opt`. Use [`nodeOptions`](#nodeoptions) for Node's own options, which do travel through `NODE_OPTIONS`.

Nub applies them to every Node process it starts, including the ones your package scripts launch as `node`. A script that runs Node through a hardcoded absolute path instead does not get them.

### `nodeCompat`

Use plain Node behavior while keeping Nub's Node version selection.

```jsonc title="nub.jsonc"
{
  // ...
  "nodeCompat": true
}
```

This is the project-wide form of the `--node` escape hatch. Nub does not load its runtime hooks, environment files, preloads, custom loaders, or conditions.

### `envFile`

Keep automatic environment-file discovery with `true`.

```jsonc title="nub.jsonc"
{
  // ...
  "envFile": true
}
```

Disable environment-file loading with `false`.

```jsonc title="nub.jsonc"
{
  // ...
  "envFile": false
}
```

Read one exact file instead of the automatic set.

```jsonc title="nub.jsonc"
{
  // ...
  "envFile": ".env.development"
}
```

Compose several files in order. Later files replace earlier values.

```jsonc title="nub.jsonc"
{
  // ...
  "envFile": [
    ".env",
    ".env.development",
    ".env.local"
  ]
}
```

Paths are resolved from the directory containing `nub.jsonc`, not the shell's current directory.

Paths also expand `${VAR}` and `$VAR` against the environment, which a config file never gets from the shell.

```jsonc title="nub.jsonc"
{
  // ...
  "envFile": ".env.${APP_ENV}"
}
```

```bash
APP_ENV=staging nub app.ts   # reads .env.staging
```

### `loader`

Teach Nub an extension it does not already know, by mapping it onto a loader it has.

```jsonc title="nub.jsonc"
{
  // ...
  "loader": {
    ".graphql": "text",   // import a schema as a string
    ".rules": "yaml",     // a project file that happens to be YAML
    ".view": "tsx"        // project source under a name of your own
  }
}
```

Nub already imports `.txt`, `.jsonc`, `.json5`, `.toml`, `.yaml`, and `.yml`, along with the TypeScript and JSX extensions, so none of those need an entry here.

The supported loader names are:

```text
text
jsonc
json5
toml
yaml
ts
tsx
jsx
```

### `conditions`

Add package export conditions.

```jsonc title="nub.jsonc"
{
  // ...
  "conditions": [
    "development",
    "react-server"
  ]
}
```

```json title="node_modules/example/package.json"
{
  "exports": {
    ".": {
      "development": "./development.js",
      "default": "./production.js"
    }
  }
}
```

### `tsconfig`

Choose the TypeScript configuration Nub's runtime reads. Nub uses it for the options that affect execution — JSX, decorators, and [path mapping](https://www.typescriptlang.org/tsconfig/#paths) — not for type checking.

```jsonc title="nub.jsonc"
{
  // ...
  "tsconfig": "./tsconfig.runtime.json"
}
```

```jsonc title="tsconfig.runtime.json"
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

### `verifyDeps`

Warn when installed dependencies may be stale.

```jsonc title="nub.jsonc"
{
  // ...
  "verifyDeps": "warn"
}
```

Stop instead of running.

```jsonc title="nub.jsonc"
{
  // ...
  "verifyDeps": "error"
}
```

Skip the check.

```jsonc title="nub.jsonc"
{
  // ...
  "verifyDeps": false
}
```

The `"install"` and `"prompt"` values are accepted for pnpm compatibility and currently behave as `"warn"`.

## `install`

The install block configures Nub's package manager and dependency lifecycle scripts.

It applies when Nub is the project's package manager. A project with an `npm`, `pnpm`, `yarn`, or `bun` lockfile keeps that tool's own configuration, and this block is ignored.

### `install.nodeLinker`

Use Nub's shared symlink layout.

```jsonc title="nub.jsonc"
{
  // ...
  "install": {
    "nodeLinker": "symlink"
  }
}
```

Use a project-local isolated store.

```jsonc title="nub.jsonc"
{
  // ...
  "install": {
    "nodeLinker": "isolated"
  }
}
```

Use a flat, real-directory layout.

```jsonc title="nub.jsonc"
{
  // ...
  "install": {
    "nodeLinker": "hoisted"
  }
}
```

The `"pnp"` value is reserved for future Plug'n'Play support. An install that uses it is rejected until support lands.

```text
nub: `install.nodeLinker: "pnp"` is reserved and not supported yet [ERR_NUB_CONFIG_UNSUPPORTED]
```

### `install.symlinkDisablePattern`

Materialize selected packages inside the project instead of linking them from the shared store.

```jsonc title="nub.jsonc"
{
  // ...
  "install": {
    "symlinkDisablePattern": [
      "electron",
      "@company/native-*"
    ]
  }
}
```

### `install.hoist`

Fill the hidden fallback tree that packages reach when they import something they never declared. It applies to the isolated layout only, so set `nodeLinker` alongside it.

```jsonc title="nub.jsonc"
{
  // ...
  "install": {
    "nodeLinker": "isolated",
    "hoist": true
  }
}
```

Keep the strict layout, where an undeclared import fails.

```jsonc title="nub.jsonc"
{
  // ...
  "install": {
    "nodeLinker": "isolated",
    "hoist": false
  }
}
```

Hoist only matching packages.

```jsonc title="nub.jsonc"
{
  // ...
  "install": {
    "nodeLinker": "isolated",
    "hoist": [
      "*eslint*",
      "@types/*"
    ]
  }
}
```

Nub rejects the field under any other layout rather than accepting a setting it would ignore.

```text
nub: `install.hoist` is supported only with `install.nodeLinker: "isolated"` [ERR_NUB_CONFIG_UNSUPPORTED]
```

### `install.minimumReleaseAge`

Reject versions published too recently.

```jsonc title="nub.jsonc"
{
  // ...
  "install": {
    "minimumReleaseAge": "3d"
  }
}
```

Durations use an integer plus one unit.

```text
30s  # seconds
20m  # minutes
12h  # hours
3d   # days
2w   # weeks
```

Exclude selected packages when they must update immediately.

```jsonc title="nub.jsonc"
{
  // ...
  "install": {
    "minimumReleaseAge": "3d",
    "minimumReleaseAgeExclude": [
      "@company/*",
      "typescript"
    ]
  }
}
```

### `install.nodeOptions`

Pass Node options to dependency lifecycle scripts.

```jsonc title="nub.jsonc"
{
  // ...
  "install": {
    "nodeOptions": [
      "--max-old-space-size=8192"
    ]
  }
}
```

## `dlx`

The dlx block configures temporary package runs through `nubx`, `nub dlx`, and `nub x`. It is read from the global file only: reaching the registry is a decision about your machine, not about one repository, so a project `nub.jsonc` carrying a `dlx` block stops the command rather than loosening a policy you set for yourself.

### `dlx.consent`

Ask before an implicit `nubx` registry fetch.

```jsonc title="~/.config/nub/nub.jsonc"
{
  // ...
  "dlx": {
    "consent": "prompt"
  }
}
```

Disable implicit registry fetches.

```jsonc title="~/.config/nub/nub.jsonc"
{
  // ...
  "dlx": {
    "consent": "never"
  }
}
```

Explicit `nub dlx` runs still work because the command itself supplies consent.

### `dlx.envFile`

Use a separate environment file for temporary tools.

```jsonc title="~/.config/nub/nub.jsonc"
{
  // ...
  "dlx": {
    "envFile": "./tools.env"  // resolved next to the global file
  }
}
```

Disable environment-file loading for temporary tools.

```jsonc title="~/.config/nub/nub.jsonc"
{
  // ...
  "dlx": {
    "envFile": false
  }
}
```

The field accepts the same boolean, string, and string-array forms as the top-level `envFile` field. Setting it to `true` reads the project's own automatic environment files, the same set a normal run discovers.
