Nub is an all-in-one toolkit for Node.js, written in Rust. One binary runs your TypeScript files and scripts, installs your dependencies, and provisions Node itself — replacing `node`, `npm`/`pnpm`, `npx`, and `nvm` without adopting a new runtime.

```bash
npm install -g @nubjs/nub
nub index.ts             # run a TypeScript file
nub install              # install dependencies (pnpm-compatible)
nub run dev              # run a package.json script
nubx prisma generate     # run a CLI from node_modules/.bin
```

Every augmentation rides on Node's own public extension surfaces, and the package manager reads and writes whatever lockfile your project already uses.

## The toolkit

- **A runtime** — execute `.{js,cjs,mjs,jsx,ts,cts,mts,tsx}` files with full TypeScript support, on the stock `node` binary. See [files](/docs/runtime).
- **A package manager** — a pnpm-compatible installer that round-trips your existing npm, pnpm, or bun lockfile. See [install](/docs/install).
- **A script runner** — run `package.json` scripts 24× faster than `pnpm run`, with the full workspace and lifecycle-hook surface preserved. See [run](/docs/runner/run).
- **A bin runner** — run a local CLI an order of magnitude faster than `npx`, or fetch and run an uninstalled one from the registry. See [nubx](/docs/runner).
- **A Node version manager** — pin a version and Nub provisions it from nodejs.org on demand, replacing `nvm` and `fnm`. See [node](/docs/node).
- **A watcher** — restart on changes to your source, your `.env*` files, and your `tsconfig.json`, driven by the dependency graph. See [watch](/docs/watch).
- **A GitHub Action** — swap `actions/setup-node` for `nubjs/setup-nub` to install Nub, warm the project's Node, and cache Nub's store in CI. See [GitHub Action](/docs/deployment/github-action).

## What Nub replaces

| Nub | Instead of |
|---|---|
| `nub <file>` | `node`, `tsx`, `ts-node`, `dotenv-cli` |
| `nub run <script>` | `npm run`, `pnpm run`, `yarn run` |
| `nubx` | `npx`, `pnpm dlx`, `pnpm exec`, `yarn dlx` |
| `nub install` | `npm`, `pnpm`, `yarn` |
| `nub watch` | `nodemon`, `node --watch`, `tsx watch` |
| `nub node` | `nvm`, `fnm`, `n`, `volta` |
| `nub pm` | `corepack` |

## Install

```bash
npm install -g @nubjs/nub
```

Both `pnpm add -g @nubjs/nub` and `yarn global add @nubjs/nub` work too. That installs the Rust binary plus the platform-specific N-API addons, and puts `nub` and `nubx` on your `PATH`. On macOS and Linux, install with Homebrew:

```bash
brew install nubjs/tap/nub
```

Nub is in Homebrew's core tap as well, so plain `brew install nub` works. Two things still favor the tap. The core formula builds without [`nub compile`](/docs/compile), and it picks up each new release later — Nub's own tap is bumped during the release run, while a core update needs its own pull request.

With [mise](https://mise.jdx.dev), `nub` and `nubx` both land on `PATH`:

```bash
mise use -g nub
```

For containers, the official image `ghcr.io/nubjs/nub` is a `node` base with Nub layered on. See [Docker](/docs/deployment/docker):

```dockerfile
FROM ghcr.io/nubjs/nub
```

In CI, swap `actions/setup-node` for the [setup-nub action](/docs/deployment/github-action):

```diff
- - uses: actions/setup-node@v4
+ - uses: nubjs/setup-nub@v0
```

### Canary builds

Every code commit to `main` publishes a canary build for all platforms, versioned `<version>-canary.<date>.<n>`:

```bash
npm install -g @nubjs/nub@canary
```

The same binaries are attached to the rolling [canary release](https://github.com/nubjs/nub/releases/tag/canary) on GitHub. Canary tracks the newest commit and passes build and smoke checks only — expect rough edges, and pin back to `@nubjs/nub@latest` to return to the stable channel.

## Package management

The installer is pnpm-compatible at the CLI surface and lockfile-compatible with whatever your project already uses. It infers the incumbent package manager and mirrors it — npm, pnpm, and bun lockfiles round-trip cleanly; yarn is read-only.

```bash
nub install              # resolve + link node_modules into existing lockfile
nub add -E -D react      # exact pin, devDeps — pnpm flag spelling
nub remove lodash
nub update
nub ci                   # frozen-lockfile install
```

It's optional: keep running your existing package manager and reach for Nub for everything else. See [install](/docs/install) for lockfile fidelity per incumbent, and [pm](/docs/pm) for provisioning the exact package-manager version a project pins.

## Configuration

Everything above works with no configuration. When you want to change a default, put a `nub.jsonc` at the project root:

```jsonc title="nub.jsonc"
{
  "$schema": "https://nubjs.com/schema/latest.json",

  "preload": ["./instrumentation.ts"],   // load a module before the entry file
  "envFile": [".env.local"],             // read these env files instead of the default set
  "tsconfig": "./tsconfig.runtime.json", // the TypeScript config the runtime uses

  "install": {
    "minimumReleaseAge": "3d"            // refuse dependencies published in the last 3 days
  }
}
```

Unknown keys and invalid values stop the command with an error. See [nub.jsonc](/docs/config) for every field, including the ones only the global file accepts.

## Requirements

- **Node 18.19+** (Node 18 LTS) for augmented modes.
- macOS (arm64, x64), Linux (x64, arm64), Windows (x64, arm64).
