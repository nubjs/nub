When npm is the incumbent — a `packageManager: "npm@…"` field or an existing `package-lock.json` — Nub reads and writes npm's `package-lock.json` and reads npm's config. The CLI you type stays pnpm's; the files are npm's.

## `package-lock.json`

Nub reads `lockfileVersion` 2 and 3 and writes the file back in npm's exact format. A no-op install reproduces npm's output byte for byte, so the file doesn't churn and `npm ci` accepts it unchanged.

```jsonc title="package-lock.json"
{
  "name": "app",
  "version": "1.0.0",
  "lockfileVersion": 3,
  "requires": true,
  "packages": {
    "": {
      "name": "app",
      "version": "1.0.0",
      "dependencies": { "is-odd": "3.0.1" }
    },
    "node_modules/is-odd": {
      "version": "3.0.1",
      "resolved": "https://registry.npmjs.org/is-odd/-/is-odd-3.0.1.tgz",
      "integrity": "sha512-CQpnWPrD…CBaXgWMA==",
      "license": "MIT",
      "dependencies": { "is-number": "^6.0.0" },
      "engines": { "node": ">=4" }
    }
  }
}
```

<Callout>
Read the [full docs](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json) on docs.npmjs.com.
</Callout>

A no-op install keeps the incoming `lockfileVersion`. The first mutating command (`nub add`, `nub remove`) rewrites the lock as v3, npm's default since npm 9, so expect that field in the diff. An `npm-shrinkwrap.json` is read and preserved as-is.

Older formats install too: a `lockfileVersion: 1` lock (npm 5/6) and a pre-2017 `npm-shrinkwrap.json` with no `lockfileVersion` at all. The first mutating command rewrites them as v3, as npm 7+ does.

## `.npmrc`

Nub reads npm's `.npmrc` cascade:

```text
builtin   npm's builtin npmrc
global    $PREFIX/etc/npmrc, or NPM_CONFIG_GLOBALCONFIG
user      ~/.npmrc, or NPM_CONFIG_USERCONFIG
project   ./.npmrc
```

Everything at those scopes applies: registries, scoped registries, auth tokens, TLS, proxies, and install keys like `engine-strict` and `save-exact`. Precedence matches npm, highest first: CLI flags, `npm_config_*`, then project, user, global, and builtin `.npmrc`.

Corporate or self-signed certificate authorities use npm's TLS keys, for all registries or one:

```ini title=".npmrc"
cafile=./corp-ca.pem                          # PEM bundle, all registries
//registry.example.com/:cafile=./corp-ca.pem  # one registry
# inline PEM (repeat ca[]= to stack)
ca="-----BEGIN CERTIFICATE-----..."
# disable verification (user/global scope only)
strict-ssl=false
```

<Callout>
Read the [full docs](https://docs.npmjs.com/cli/v11/configuring-npm/npmrc) on docs.npmjs.com.
</Callout>

## `package.json`

Nub honors npm's own fields:

```jsonc title="package.json"
{
  // applied during resolution, written to the lock
  "overrides": { "is-number": "7.0.0" },

  // plus npm's --workspace / --workspaces flags
  "workspaces": ["packages/*"],

  // with os, cpu, and libc, enforced during resolution
  "engines": { "node": ">=22.15" }
}
```

<Callout>
Read the [full docs](https://docs.npmjs.com/cli/v11/configuring-npm/package-json#overrides) on docs.npmjs.com.
</Callout>

The Yarn-style `resolutions` field means nothing to npm, so Nub drops it with a warning. Put pins in `overrides`.

## Install behavior

The default `node_modules` layout is isolated, and npm's `install-strategy`, `global-style`, and `legacy-bundling` settings do not change it. A project that relies on undeclared dependencies can switch to the flat layout with [`install.linker`](/docs/config#installlinker) or one line in `.npmrc`:

```ini title=".npmrc"
node-linker=hoisted
```

Dependency build scripts are denied by default, unlike npm. Curated packages that pass the [default-trust floor](/docs/install#default-trust-floor) build automatically. Everything else is skipped with `WARN_NUB_IGNORED_BUILD_SCRIPTS` until you run `nub approve-builds`.

## Gaps

- **Git and `file:` dependencies in a v1 lock** are not read, because v1 records their source in `version` rather than `resolved`. Re-lock under npm 7+, then run `nub install`.
- **A pre-npm-5 shrinkwrap with no `requires` edges** installs partially, with `WARN_NUB_LOCKFILE_LEGACY_INCOMPLETE_GRAPH` naming what it could not place. Re-lock under npm 7+.
- **No npm CLI grammar.** Nub does not emulate npm-specific subcommand spellings and flags.
