---
title: Bun
description: When Bun owns a project, Nub reads and writes its text lockfile unchanged, gates build scripts on its trusted-dependencies list, and resolves overrides, patches, and catalogs the way Bun does.
---

When Bun is the incumbent — a `packageManager: "bun@…"` field or an existing `bun.lock` — Nub installs against Bun's lockfile and writes none of its own. Overrides, resolutions, patches, workspaces, and catalogs resolve the way Bun resolves them.

## `bun.lock`

Nub reads and writes the text lockfile, the default since Bun 1.2, and leaves it byte-identical when nothing changes:

```console
# captured: nub 0.0.44 — install in a bun.lock project, then diff the lock
$ nub install
dependencies:
+ is-odd@3.0.1

nub 0.0.44 · ✓ installed 2 packages in 38ms

$ diff bun.lock bun.lock.orig    # ✓ byte-identical (no output)
$ ls pnpm-lock.yaml              # ✓ no foreign lockfile written
ls: pnpm-lock.yaml: No such file or directory
```

The binary `bun.lockb` from before Bun 1.2 is not read. A project with only a `bun.lockb` fails up front:

```console wide
# captured: nub 0.0.44 — a project with only bun.lockb
$ nub install
ERR_NUB_LOCKFILE_PARSE          # ❌ binary format rejected

  × failed to parse lockfile
  ╰─▶ failed to parse lockfile /path/to/bun.lockb: bun.lockb
      (binary format) is not supported — run `bun install --save-text-
      lockfile` to generate a bun.lock text file first, or upgrade to bun 1.2+
      where text is the default
```

Run `bun install --save-text-lockfile` once to migrate.

## `bunfig.toml`

Nub reads the install settings from the project `bunfig.toml` and the global `.bunfig.toml` in `XDG_CONFIG_HOME`, or `HOME` when that is unset. Project config wins.

- `[install].registry` — a URL string, or a `{ url, token, username, password }` object
- `[install.scopes]` — scoped registries, in either form
- `[install].cafile`, `[install].ca` — the same TLS trust as the `.npmrc` `cafile` and `ca` keys
- `[install].minimumReleaseAge`, `[install].minimumReleaseAgeExcludes` — the [cooling window](/docs/install#cooling-window), converted from Bun's seconds

The `BUN_CONFIG_REGISTRY` and `BUN_CONFIG_TOKEN` environment variables set the default registry and its token, and outrank the file.

<Callout>
Read the [full docs](https://bun.com/docs/runtime/bunfig) on bun.com.
</Callout>

For registry, auth, or TLS settings shared with other tools, use `.npmrc`, which Nub reads under every incumbent:

```ini title=".npmrc"
//registry.example.com/:_authToken=${NPM_TOKEN}
@myscope:registry=https://registry.example.com/
cafile=./corp-ca.pem
```

## Install behavior

Bun gates dependency build scripts behind the `trustedDependencies` list in `package.json`, and Nub does the same. Listed packages run their `install` and `postinstall` scripts; everything else installs without building.

```json title="package.json"
{
  "dependencies": { "esbuild": "0.21.5" },
  "trustedDependencies": ["esbuild"]
}
```

<Callout>
Read the [full docs](https://bun.com/docs/pm/lifecycle#trusteddependencies) on bun.com.
</Callout>

```console wide
# captured: nub 0.0.44 — esbuild NOT in trustedDependencies — build skipped
$ nub install
dependencies:
+ esbuild@0.21.5

nub 0.0.44 · ✓ installed 2 packages in 33ms
WARN ignored build scripts for 1 package(s): esbuild@0.21.5.
     Run `nub approve-builds` to review and enable them, or set
     `strictDepBuilds=true` to fail installs that have unreviewed builds.
     code=WARN_NUB_IGNORED_BUILD_SCRIPTS count=1 packages=["esbuild@0.21.5"]

# captured: nub 0.0.44 — esbuild IN trustedDependencies — build runs
$ nub install
dependencies:
+ esbuild@0.21.5

nub 0.0.44 · ✓ installed 2 packages in 35ms
```

Nub's [default-trust floor](/docs/install#default-trust-floor) builds nothing over a `bun.lock`. Its cooling-window gate needs publish times, which `bun.lock` does not record, so only `trustedDependencies` builds anything, as in Bun.

Nub does not read `[install].linker`. Set layout with [`install.linker` in `nub.jsonc`](/docs/config#installlinker), `node-linker` in `.npmrc`, or `--node-linker` for one command.

## Gaps

- **No `bun.lockb`.** Convert to a text `bun.lock` first.
- **Only the `[install]` settings above.** Nub ignores the rest of `bunfig.toml`: `linker`, runtime, test, and serve fields, the security scanner, and cache and global-dir settings. Other `BUN_CONFIG_*` variables, such as the retry, lockfile, and skip toggles, have no effect.
