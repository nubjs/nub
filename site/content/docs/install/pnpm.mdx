title: pnpm
description: When pnpm owns a project, Nub reads and writes its version 9 lockfile and honors pnpm's workspace file, package.json settings, and pnpmfile hooks.
---

Nub mirrors pnpm most closely: the CLI, the isolated `node_modules` layout, and the lockfile. When pnpm is the incumbent — a `packageManager: "pnpm@…"` field or an existing `pnpm-lock.yaml` — Nub reads and writes `pnpm-lock.yaml` and honors pnpm's config.

## `pnpm-lock.yaml`

Nub reads and writes lockfile v9 (`lockfileVersion: '9.0'`), the format pnpm 9 and later emit. A lockfile Nub writes installs cleanly under pnpm:

```console
$ nub install
dependencies:
+ is-odd@3.0.1

$ grep lockfileVersion pnpm-lock.yaml
lockfileVersion: '9.0'

$ pnpm install --frozen-lockfile
Lockfile is up to date, resolution step is skipped
```

The round-trip holds in both directions, including workspaces with `catalog:` and `workspace:` entries.

Nub declines the older v6 (pnpm 8) and v5.4 (pnpm 7) formats up front and leaves `node_modules` and the lockfile untouched:

```console
# captured: nub 0.0.44 on a lockfileVersion: '6.0' lockfile
$ nub install
Error: ERR_NUB_LOCKFILE_UNSUPPORTED_FORMAT

  × pnpm-lock.yaml is lockfileVersion 6.0 (pnpm 8); nub reads v9 (pnpm 9+).
  help: Re-lock under pnpm 9+ (`pnpm install`), then `nub install`.
```

Run `pnpm install` once under pnpm 9 or later to upgrade the lockfile, then `nub install`.

## `pnpm-workspace.yaml`

Nub reads the `packages:` globs, the `catalog:` and `catalogs:` maps, `namedRegistries`, and pnpm 11's resolution settings. Layout keys are [not read](#install-behavior).

```yaml title="pnpm-workspace.yaml"
packages:
  - 'packages/*'
catalog:
  lodash.merge: 4.6.2
namedRegistries:
  work: https://npm.example.com/
```

A `namedRegistries` alias routes a dependency spec with that prefix to its registry. The map can also live in pnpm's global `config.yaml`, and the built-in `gh:` alias points at GitHub Packages. Auth comes from the matching `//host/:_authToken=` entry in `.npmrc`.

```json title="package.json"
{
  "dependencies": { "@work/constants": "work:1.x.x" }
}
```

Read the [full docs](https://pnpm.io/settings) on pnpm.io.
</Callout>

## `package.json`

Nub reads pnpm's settings from the `pnpm` object:

- `pnpm.overrides` — version pins, written to the lockfile
- `pnpm.packageExtensions` — dependency metadata repairs
- `pnpm.patchedDependencies` — patch files, managed by `nub patch`
- `pnpm.onlyBuiltDependencies`, `pnpm.allowBuilds`, `pnpm.neverBuiltDependencies` — [build-script policy](#install-behavior)
- `pnpm.supportedArchitectures` — which platforms' optional dependencies install

```json title="package.json"
{
  "pnpm": { "overrides": { "is-number": "7.0.0" } }
}
```

The `overrides`, `packageExtensions`, and `patchedDependencies` settings can also live in `pnpm-workspace.yaml`, as pnpm allows. Top-level `resolutions` applies too, as it does in pnpm. Top-level `overrides` is npm and Bun's field, so Nub ignores it here with a warning.

Running `nub pm use nub` moves the project to Nub and migrates these pins to the top-level `overrides` and `patchedDependencies` fields.

## `.pnpmfile.cjs`

Nub runs the `readPackage`, `preResolution`, and `afterAllResolved` hooks from `.pnpmfile.cjs` or `.pnpmfile.mjs`:

- Dependency-map edits from `readPackage` apply.
- Package-map edits from `afterAllResolved` apply.
- The `preResolution` hook is read-only. It receives pnpm's lockfile object, but Nub runs it out of process, so edits to that object are reported and discarded.

Adding importers or packages, identity rewrites, `updateConfig` hooks, and config-dependency pnpmfiles are not supported.

Under an npm, Yarn, or Bun incumbent, a stray pnpmfile is ignored with a warning. An explicit `--pnpmfile <path>` always loads.

```console
$ nub install
nub: `.pnpmfile.cjs` ignored — this project uses npm, which doesn't
     apply pnpmfile hooks. Remove it, name it explicitly with
     `--pnpmfile`, or switch to pnpm (`nub pm use pnpm`).
```

## Install behavior

The default `node_modules` layout is isolated, pnpm's symlink-into-a-virtual-store scheme. The `--node-linker hoisted` flag gives the flat npm-style layout.

Nub does not read `nodeLinker` or the hoisting keys from `pnpm-workspace.yaml` or pnpm's global `config.yaml`. Set layout with [`install.linker` and `install.publicHoist` in `nub.jsonc`](/docs/config#install), their `.npmrc` spellings, or command-line flags, under every pnpm major.

<Callout>
Read the [full docs](https://pnpm.io/settings/node-modules#nodelinker) on pnpm.io.
</Callout>

Dependency build scripts are skipped by default, as in pnpm 10. A package builds when it is listed in `pnpm.onlyBuiltDependencies` or `pnpm.allowBuilds`, or when the [default-trust floor](/docs/install#default-trust-floor) admits it. Running `nub approve-builds` adds the entry and builds the package in the same invocation. A package in `pnpm.neverBuiltDependencies` never builds, whatever allows it.

## Gaps

- **No `deploy` or `sbom`.** Both commands fail with an unsupported-command error.
- **No `pnp` linker.** A `pnp` value in `.npmrc`, `nub.jsonc`, or `--node-linker` is refused:

  ```console
  $ nub install                                                    # ❌
    × node-linker=pnp is not supported by nub; use `isolated` (default) or
    │ `hoisted`
  ```
