---
title: Watch mode
description: Restart a file when it or anything it imports changes, including environment files, tsconfig, and package.json, with no glob list to maintain.
---

Watch mode runs a file and restarts it when the file or anything it imports changes:

```bash
nub watch src/server.ts
nub --watch src/server.ts   # same thing, in node --watch's spelling
```

Everything [`nub <file>`](/docs/runtime) does is active: TypeScript, JSX, `.env*` loading, and `tsconfig.json` paths. A project [`nub.jsonc`](/docs/config) applies on every restart, including its preloads, environment files, loaders, conditions, and tsconfig selection.

The watcher takes a file, not a script name. A `--watch` after a script name goes to the script, so `nub run test --watch` runs your test tool's own watch mode (see [argument forwarding](/docs/run#argument-forwarding)).

## Watched files

The watch set comes from what the run actually loads, not from a glob. A restart fires on a change to:

- Any file in the entry's resolved import graph, including `.ts` and `.tsx` files Nub transpiles in memory
- Environment files: `.env*`, plus any file named with `--env-file` or `--env-file-if-exists`
- The `tsconfig.json` `extends` chain, so editing a `paths` mapping restarts the process
- `package.json`

Every restart re-reads the environment files, so an edited value is live on the next run. On Node older than 20.6, environment files are read once at startup; restart `nub watch` itself to pick up an edit.

A build output such as `dist/foo.js` triggers a restart only if the run imported it.

## Output

A restart prints Node's status lines instead of clearing the terminal, so the previous run's error stays visible:

```console
$ nub watch src/server.ts
Completed running 'src/server.ts'. Waiting for file changes before
restarting...
Restarting 'src/server.ts'
```

## How it works

The engine is Node's own `--watch`, run with `--watch-preserve-output`. Nub reports the in-memory-transpiled import graph and the off-graph files above to Node's watcher over its `WATCH_REPORT_DEPENDENCIES` channel.

For vanilla Node watch mode, run `node --watch` directly:

```bash
node --watch script.js
```
