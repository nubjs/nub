---
title: Web Storage
description: Session storage is in-memory, and persistent local storage turns on once you point it at a backing file. Both need Node 22.4 or newer.
---

Node 22.4 through 24 hide `sessionStorage` and `localStorage` behind `--experimental-webstorage`, and Nub injects the flag on those releases. From Node 25 they are on by default; below 22.4 they do not exist.

A `--experimental-webstorage` or `--no-experimental-webstorage` you pass yourself wins, and Nub injects nothing.

<Callout>
Read the [full docs](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API) for Web Storage on developer.mozilla.org.
</Callout>

## `sessionStorage`

The `sessionStorage` global is in memory. Each run starts with an empty store, and it is discarded when the process exits.

```ts
sessionStorage.setItem("step", "1");
sessionStorage.getItem("step");      // "1"
sessionStorage.length;               // 1
sessionStorage.key(0);               // "step"
sessionStorage.removeItem("step");
sessionStorage.clear();
```

## `localStorage`

The `localStorage` global persists across runs in a file. Pass `--localstorage-file <path>`, directly or in `NODE_OPTIONS`, and Nub forwards it to Node. Without the flag, `localStorage` is `undefined`.

```ts
localStorage.setItem("token", "abc123");
localStorage.getItem("token");        // "abc123"
localStorage.length;                  // 1
localStorage.key(0);                  // "token"
localStorage.removeItem("token");
localStorage.clear();
```

```console
$ nub --localstorage-file=./app.db write.ts
abc123
$ nub --localstorage-file=./app.db read.ts
abc123
```
