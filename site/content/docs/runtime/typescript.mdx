title: TypeScript
description: How Nub runs every TypeScript feature on stock Node, including non-erasable syntax, resource-management downleveling, and source maps.
---

Nub runs every TypeScript feature, not just the erasable subset Node's built-in type stripping accepts. Files ending in `.ts`, `.tsx`, `.mts`, and `.cts` run directly.

```bash
nub index.ts
nub server.tsx
```

Nub transpiles each file before Node sees it, so these features work from the Node 18.19 floor up.

<Callout title="Types are stripped, not checked">
Nub does not type-check. Keep `tsc --noEmit` in your editor and CI for type validation.
</Callout>

## Non-erasable syntax

Syntax like `enum`, `namespace`, parameter properties, and `import =` needs a runtime form, not just type removal, and Node's type stripping rejects it. Nub emits the runtime form.

```ts
enum Color { Red, Green, Blue }

namespace Geometry {
  export const PI = 3.14159;
}

class User {
  constructor(public id: string, private name: string) {}
}

import fs = require("node:fs");
```

JSX and decorators have their own pages: [JSX](/docs/runtime/jsx) and [Decorators](/docs/runtime/decorators).

## Explicit resource management

The `using` and `await using` declarations run from Node 18.19 up. Node 22's V8 cannot parse `using`, so Nub lowers it to a helper-based form.

```ts
class Handle {
  [Symbol.dispose]() { console.log("disposed"); }
}

{
  using h = new Handle();
  console.log("using h");
}
console.log("after scope");
```

```console
$ nub resource.ts
using h
disposed
after scope
```

<Callout>
Read the [full docs](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/using) for `using` on developer.mozilla.org.
</Callout>

## Source maps

Nub generates an inline source map for every transpiled file and injects `--enable-source-maps`. Stack traces point at your TypeScript source, and breakpoints set in `.ts` files land correctly under `nub --inspect`.

```console
$ nub app.ts
/path/to/app.ts:2
	throw new Error("kaboom");
	^

Error: kaboom
    at boom (/path/to/app.ts:2:8)
    at Object.<anonymous> (/path/to/app.ts:4:1)
```

To turn it off, pass `--no-enable-source-maps`.

On Node 26.0 through 26.7, Nub does not inject the flag, so stack traces are not remapped there. A Node regression on those releases ([nodejs/node#63169](https://github.com/nodejs/node/issues/63169)) makes a no-message `assert(false)` throw a `TypeError` when source maps are on; 26.8 fixes it.

## Plain JavaScript

Your project's `.js`, `.mjs`, and `.cjs` files go through the same pipeline. Modern syntax that older Node cannot parse is lowered as it is in a `.ts` file: `using` and `await using`, `v`-flag RegExps like `/\p{Letter}/v`, and decorators.

```js title="app.js"
using handle = openHandle();
const letters = /\p{Letter}/v;
```

Files inside `node_modules` are never transpiled.

## Choosing a tsconfig

Nub reads the nearest `tsconfig.json` for [module resolution](/docs/runtime/resolution) and transform defaults. To have the runtime read a different file, name it in [nub.jsonc](/docs/config#tsconfig).

```jsonc title="nub.jsonc"
{
  // ...
  "tsconfig": "./tsconfig.runtime.json"  // read instead of ./tsconfig.json
}
```

JSX and decorator options can also be set in [nub.jsonc](/docs/config#jsx) directly.

A tsconfig Nub cannot read in full stops the run.

```console
$ nub main.ts
Nub: /app/tsconfig.json: File './base.json' not found.
Error: the project's tsconfig.json could not be read in full (see above).
Fix the config, or use --node to run without Nub's TypeScript features,
path aliases included.
```

<Callout>
Read the [full docs](https://www.typescriptlang.org/tsconfig/) for `tsconfig.json` on typescriptlang.org.
</Callout>
