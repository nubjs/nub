Import a config or data file directly.

```ts
import config from "./config.yaml";  // parsed object
import flags from "./feature.jsonc"; // parsed object (comments stripped)
import pkg from "./Cargo.toml";      // parsed object
import schema from "./schema.json5"; // parsed object (JSON5 superset)
import prompt from "./prompt.txt";   // string
```

## Extensions

Loaders are keyed on file extension:

- `.jsonc` — JSON with comments
- `.json5` — the JSON5 superset
- `.toml`
- `.yaml` / `.yml`
- `.txt` — loaded as a string, no parsing

The `.json` extension is not in this set: JSON modules are Node-native.

## Custom extensions

Map an extension of your own onto one of Nub's loaders from a [nub.jsonc](/docs/config#loader).

```jsonc title="nub.jsonc"
{
  // ...
  "loader": {
    ".config": "jsonc",  // JSON with comments
    ".data": "yaml"
  }
}
```

The loader names are:

```text
text  jsonc  json5  toml  yaml  ts  tsx  jsx
```

Any other value stops the command with an error.

## Default export

A data module exposes a single default export — the parsed value, like Node's own JSON modules. There are no named exports; destructure the default to pull out top-level keys.

```yaml title="config.yaml"
host: localhost
port: 5432
```

```ts
import config from "./config.yaml"; // { host: "localhost", port: 5432 }
const { host, port } = config;      // "localhost", 5432
```

The object formats are typed `Record<string, unknown>`, so destructured keys are `unknown` — narrow or cast them at the use site. A data file whose top-level value is an array or scalar imports as that value via the default; cast it, since the wildcard type assumes an object.

## Values

YAML follows the YAML 1.2 core schema, as the `yaml` package does. `.nan` and `.inf` are numbers, an unquoted `nan`, `yes` or `2001-12-14` is a string, and an integer past `Number.MAX_SAFE_INTEGER` rounds to the nearest number.

TOML values that JSON has no form for keep their type:

| TOML | JavaScript |
| --- | --- |
| `9007199254740993` (past `Number.MAX_SAFE_INTEGER`) | `9007199254740993n` |
| `nan`, `-inf` | `NaN`, `-Infinity` |
| `1979-05-27T07:32:00Z` | `Date` |
| `1979-05-27T07:32:00` (local) | `Date` in the local time zone |
| `1979-05-27` | `Date` at UTC midnight |
| `07:32:00` | `"07:32:00.000"` |

JSON5's `NaN` and `Infinity` are numbers too.

## Text imports

Add the `with { type: "text" }` import attribute to read a file's raw contents as a string, whatever its extension.

```ts
import readme from "./README.md" with { type: "text" };  // string
import query from "./query.sql" with { type: "text" };   // string
import raw from "./config.yaml" with { type: "text" };   // YAML, unparsed
```

The attribute wins over parsing: a `.yaml` or `.json` file read this way is the raw text, not the parsed value. A text import is a single default export, like the data loaders — there are no named exports.
