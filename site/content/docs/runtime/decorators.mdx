---
title: Decorators
description: How Nub runs legacy TypeScript decorators and their design-type metadata on stock Node, the form NestJS, TypeORM, and Angular are written against.
---

Set the decorator mode to `legacy` in `nub.jsonc` and decorated classes run with no build step. This is the form the dependency-injection and ORM ecosystem (NestJS, TypeORM, Angular) is written against.

```jsonc title="nub.jsonc"
{
  "decorators": "legacy",
  "emitDecoratorMetadata": true  // optional: design-type metadata
}
```

```ts
@Entity()
class Account {
  @PrimaryGeneratedColumn()
  id: number;

  @Column()
  balance: number;
}
```

Nub also reads `compilerOptions.experimentalDecorators` and `compilerOptions.emitDecoratorMetadata` from the selected or nearest `tsconfig.json`. A field set in `nub.jsonc` wins.

<Callout>
Read the [full docs](https://www.typescriptlang.org/docs/handbook/decorators.html) for decorators on typescriptlang.org.
</Callout>

## Design-type metadata

With `emitDecoratorMetadata` on, Nub emits the `Reflect.metadata(...)` calls that DI containers read to infer constructor-parameter types. Install and import `reflect-metadata` yourself, as with plain TypeScript.

## Stage 3 decorators

Stage 3 decorators, TypeScript 5's default, are not supported. The transform is an [open gap in oxc](https://github.com/oxc-project/oxc/issues/9170), so Nub rejects Stage 3 decorator syntax with a diagnostic that points to `decorators: "legacy"`.
