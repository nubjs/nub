<TypesSetup>
Nub's types package declares the keyed Promise combinators, `Temporal`, the browser-style `Worker` global, and `reportError`. Standard APIs use TypeScript's bundled libraries and `@types/node`.
</TypesSetup>

Nub makes newer JavaScript, web-platform, and Node APIs available without version checks in application code. It keeps a native implementation when Node has one, fills a missing standard API with a feature-detected polyfill, and enables a Node API only on releases that contain its experimental flag.

```ts
const { user, posts } = await Promise.allKeyed({
  user: fetchUser(id),
  posts: fetchPosts(id),
});

const today = Temporal.Now.plainDateISO();
const route = new URLPattern({ pathname: "/users/:id" });
```

## `Promise.allKeyed`

The keyed combinators take an object instead of an iterable. They preserve its keys, so concurrent work can be named at creation and destructured at the result.

```ts
const { account, invoices } = await Promise.allKeyed({
  account: getAccount(accountId),
  invoices: listInvoices(accountId),
});
```

The settled form keeps the same object shape and records each outcome independently:

```ts
const result = await Promise.allSettledKeyed({
  profile: getProfile(userId),
  avatar: getAvatar(userId),
});

if (result.profile.status === "fulfilled") {
  console.log(result.profile.value);
}
```

Both methods follow the [TC39 await-dictionary proposal](https://github.com/tc39/proposal-await-dictionary):

| Behavior | Contract |
| --- | --- |
| Keys | Own enumerable string and symbol keys are preserved in property order |
| Result | A null-prototype object with the same keys |
| Values | Inputs pass through `Promise.resolve`, so plain values and thenables work |
| Failure | `allKeyed` rejects on the first rejection; `allSettledKeyed` records every outcome |
| Subclasses | Calling the method on a Promise subclass uses that constructor for the returned promise |

These methods are available on every Node version Nub supports. No Node release has them natively yet, so Nub installs them without replacing a user or future native implementation.

## Iterator and collection proposals

Nub also fills the current iterator and collection proposals. The keyed iterator form mirrors the Promise API:

```ts
const rows = Iterator.zipKeyed({
  id: [101, 102, 103],
  name: ["Ada", "Linus", "Grace"],
});

for (const row of rows) {
  console.log(row); // { id: 101, name: "Ada" }, then the next pair
}
```

The proposal-only methods are present across the full supported Node range:

```ts
Iterator.zip([ids, names]);
Iterator.zipKeyed({ id: ids, name: names });

Iterator.from(records).chunks(100);
Iterator.from(values).windows(3);
Iterator.from(values).includes(needle);
Iterator.from(values).join(", ");

Math.sumPrecise(amounts);
Atomics.pause();
```

The catalog below includes the newer APIs that are already native on some Node versions.

## Native implementations win

Every polyfill checks the live API before installing. Nub never overwrites a native implementation, and it stops loading a fallback as soon as the running Node supplies the feature.

Temporal is lazy on older Node versions: Nub does not load its polyfill until code first reads the global. Experimental flags are derived from the exact Node version because passing an unknown flag would abort Node during startup.

## Polyfill limits

Most fallbacks match the native API at the JavaScript level. Three userland limits cannot reproduce V8's internal slots:

- On Node 23 and below, `Error.isError` cannot recognize an `Error` created in another realm.
- On Node 23 and below, a polyfilled `Float16Array` is not recognized by `ArrayBuffer.isView()`.
- Iterator methods supplied by Nub return generator-backed helper objects. Iteration, laziness, validation, and iterator closing match the proposals, but the objects report a generator prototype and `Symbol.toStringTag` instead of the future native iterator-helper identity.

Compatibility mode disables this entire layer. Run the same program with `nub --node` or set `NODE_COMPAT=1` to use the project's pinned Node with no polyfills, preload patches, or automatically enabled flags.
