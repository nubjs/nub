title: Google Cloud Run
description: Build the official Nub image from source and deploy it as a Cloud Run service.
---

Cloud Run runs any image that follows its [container runtime contract](https://docs.cloud.google.com/run/docs/container-contract). The official Nub image includes the `linux/amd64` variant Cloud Run requires and runs as a non-root user.

## Dockerfile

```dockerfile title="Dockerfile"
FROM ghcr.io/nubjs/nub:{{NUB_VERSION}}

COPY --chown=node:node package.json package-lock.json ./
RUN nub ci

COPY --chown=node:node . .
EXPOSE 8080
CMD ["nub", "run", "start"]
```

Change `package-lock.json` to the lockfile the project already uses.

## HTTP endpoint

The start script's server must listen on `0.0.0.0` at Cloud Run's `PORT`, which defaults to `8080`:

```ts title="server.ts"
import { createServer } from "node:http";

const port = Number(process.env.PORT || 8080);

createServer((request, response) => {
  response.writeHead(200, { "content-type": "application/json" });
  response.end(JSON.stringify({ alive: true, runtime: "nub-on-node" }));
}).listen(port, "0.0.0.0");
```

## Deploy

### Project setup

Authenticate the Google Cloud CLI, select a billing-enabled project, and enable the build and runtime services:

```bash
gcloud auth login
gcloud config set project PROJECT_ID
gcloud services enable \
  run.googleapis.com \
  cloudbuild.googleapis.com \
  artifactregistry.googleapis.com
```

The deployer needs Google's [source-deployment roles](https://docs.cloud.google.com/run/docs/deploying-source-code#before_you_begin). Source builds run as the Compute Engine default service account unless the project selects another builder. A project administrator grants that account the builder role:

```bash
PROJECT_NUMBER=$(gcloud projects describe PROJECT_ID \
  --format="value(projectNumber)")
COMPUTE_SA="${PROJECT_NUMBER}-compute@developer.gserviceaccount.com"
gcloud projects add-iam-policy-binding PROJECT_ID \
  --member="serviceAccount:$COMPUTE_SA" \
  --role="roles/run.builder"
```

### From source

Deploy the directory that contains the Dockerfile. Cloud Build builds the image, stores it in Artifact Registry, and creates a Cloud Run revision:

```bash
gcloud run deploy nub-app \
  --source . \
  --region us-west1 \
  --no-invoker-iam-check   # public; omit for a private service

URL=$(gcloud run services describe nub-app \
  --region us-west1 \
  --format="value(status.url)")
curl --fail "$URL/alive"
# {"alive":true,"runtime":"nub-on-node"}
```

The `--no-invoker-iam-check` flag makes the service public without an `allUsers` IAM binding, so it also works under domain-restricted sharing policies.

<Callout>
Read the [full docs](https://docs.cloud.google.com/run/docs/authenticating/public) on cloud.google.com.
</Callout>

### Private services

Callers of a private service need the Cloud Run Invoker role. Test one with an identity token:

```bash
TOKEN=$(gcloud auth print-identity-token)
curl --fail -H "Authorization: Bearer $TOKEN" "$URL/alive"
```

## Prebuilt images

A source deployment builds `linux/amd64` for you. To build on an Apple Silicon machine instead, select the platform explicitly before pushing to Artifact Registry:

```bash
docker build --platform linux/amd64 -t IMAGE_URL .
docker push IMAGE_URL
gcloud run deploy nub-app --image IMAGE_URL --region us-west1
```

GitHub Actions can do the same: test with `setup-nub`, build the Dockerfile, authenticate to Google through workload identity federation, and push the image to Artifact Registry.
