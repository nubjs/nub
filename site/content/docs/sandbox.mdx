> **Preview:** The sandbox engine implements the syntax on this page, but the `nub.jsonc` bridge is inert. The project-config parser validates and retains a restricted shape, but Nub does not apply those values to runtime commands, installs, or temporary package runs.

> **Decision audit in progress:** This unlisted page records experimental engine behavior, not an approved public contract. Proxy modes and credential brokering are being redesigned and must not be published from this draft.

The engine can allow only the files, hosts, and environment variables a command needs. Its examples are a reference for the active engine syntax, not settings that `nub.jsonc` applies today.

```jsonc title="sandbox configuration"
{
  "sandbox": {
    "fs": {
      "./src": "r",
      "./dist": "rw",
      "<tmp>": "rw"
    },
    "net": ["registry.npmjs.org"],
    "proxy": "passthrough",
    "env": ["...", "NODE_ENV", "!*_TOKEN"]
  }
}
```

## Project configuration bridge

The project config parser recognizes sandbox values in three locations.

```jsonc title="nub.jsonc"
{
  // File runs and package scripts
  "sandbox": true,

  // Dependency lifecycle scripts
  "install": {
    "sandbox": "build-jail"
  },

  // nubx, nub dlx, and nub x
  "dlx": {
    "sandbox": {
      "fs": ["..."],
      "net": false,
      "env": ["..."]
    }
  }
}
```

Each location accepts a boolean, a string, or an object containing only `fs`, `net`, and `env`; each axis accepts a boolean, a string array, or an object. Unknown axis names and non-string array entries are rejected. The parser retains object values without interpreting their rules.

The engine reference below accepts more detailed object syntax, including inheritance. Those detailed objects are not yet valid project configuration unless they fit the restricted parser shape above, and no project configuration sandbox value has an effect yet.

## External sandbox config files

The hidden runner accepts a bare sandbox object.

```jsonc title="sandbox.jsonc"
{
  "fs": ["./src", "./dist"],
  "net": false,
  "env": ["PATH", "NODE_ENV"]
}
```

It also accepts the same object under a top-level `sandbox` key.

```jsonc title="sandbox.jsonc"
{
  "sandbox": {
    "fs": ["./src", "./dist"],
    "net": false,
    "env": ["PATH", "NODE_ENV"]
  }
}
```

An empty sandbox object denies filesystem, network, and ambient environment access.

```jsonc title="sandbox.jsonc"
{
  "sandbox": {}
}
```

## `fs`

The `fs` key controls filesystem reads and writes.

### Allow everything or nothing

```jsonc
{
  "sandbox": {
    "fs": true
  }
}
```

```jsonc
{
  "sandbox": {
    "fs": false
  }
}
```

### Allow several paths

Array entries grant read and write access. A path also covers everything below it.

```jsonc
{
  "sandbox": {
    "fs": [
      "./src",
      "./dist",
      "<cache>/my-tool"
    ]
  }
}
```

The example above is equivalent to:

```jsonc
{
  "sandbox": {
    "fs": {
      "./src": "rw",
      "./dist": "rw",
      "<cache>/my-tool": "rw"
    }
  }
}
```

### Choose read or read-write access

Object values accept `"r"`, `"rw"`, `true`, or `false`.

```jsonc
{
  "sandbox": {
    "fs": {
      "./src": "r",
      "./dist": "rw",
      "./secrets": false,
      "./generated": true
    }
  }
}
```

An object value of `true` means `"rw"`, while `false` denies both reads and writes. There is no write-only mode.

### Use project-relative paths

Relative paths resolve from the project root.

```jsonc
{
  "sandbox": {
    "fs": {
      "./src": "r",
      "dist": "rw",
      "../shared/schema": "r"
    }
  }
}
```

### Use symbolic roots

The compiler recognizes `<home>`, `~`, `<cache>`, and `<tmp>`.

```jsonc
{
  "sandbox": {
    "fs": {
      "<home>/.config/my-tool": "r",
      "~/.cache/my-tool": "rw",
      "<cache>/typescript": "rw",
      "<tmp>": "rw"
    }
  }
}
```

The `<tmp>` root requests a fresh private temporary directory for the run.

```jsonc
{
  "sandbox": {
    "fs": {
      "<tmp>": "rw"
    }
  }
}
```

Use `false` to hide temporary storage.

```jsonc
{
  "sandbox": {
    "fs": {
      "<tmp>": false
    }
  }
}
```

If `<tmp>` is absent, temporary storage follows the normal filesystem rules. A literal `/tmp` means the host's shared temporary directory, not the private directory.

```jsonc
{
  "sandbox": {
    "fs": {
      "/tmp": "r"
    }
  }
}
```

### Match several paths

Filesystem patterns support `*`, `**`, `?`, character classes, and brace expansion.

```jsonc
{
  "sandbox": {
    "fs": {
      "packages/*/src": "r",
      "packages/**/dist": "rw",
      "logs/worker-?.log": "r",
      "certs/[ab].pem": "r",
      "logs/{app,worker}.log": "r"
    }
  }
}
```

### Deny a path

Prefix an array entry with `!`.

```jsonc
{
  "sandbox": {
    "fs": [
      "./data",
      "!./data/private"
    ]
  }
}
```

Rules are checked in order. The last matching rule wins.

```jsonc
{
  "sandbox": {
    // private stays denied
    "fs": ["./data", "!./data/private"]
  }
}
```

```jsonc
{
  "sandbox": {
    // ./data appears last, so it re-allows private
    "fs": ["!./data/private", "./data"]
  }
}
```

### Keep inherited filesystem settings

Use `"..."` inside an array to insert the enclosing sandbox settings at that position.

```jsonc
{
  "sandbox": {
    "fs": [
      "...",
      "./generated"
    ]
  }
}
```

At the outermost level, `"..."` inserts the secure filesystem defaults.

```jsonc
{
  "sandbox": {
    "fs": [
      "...",
      "./dist"
    ],
    "net": false,
    "env": false
  }
}
```

### Resolve a path with a command

A `$(command)` expression runs while the sandbox config is compiled. Its single-line output becomes the path.

```jsonc
{
  "sandbox": {
    "fs": {
      "$(pnpm store path)": "r",
      "$(npm config get cache)": "rw"
    }
  }
}
```

```jsonc
{
  "sandbox": {
    "fs": {
      "$(pnpm store path)/v3": "rw"
    }
  }
}
```

A failed command, empty output, multiple output lines, or an unfinished `$(` expression is an error.

### Read an `.env` file explicitly

Read-granting policies deny `.env*` files by default. Grant an exact file when a command must read it.

```jsonc
{
  "sandbox": {
    "fs": {
      "./.env.production": "r"
    }
  }
}
```

A broad directory or glob does not reopen `.env*` files.

```jsonc
{
  "sandbox": {
    "fs": {
      "./": "r"
    }
  }
}
```

An exact grant can reopen one `.env*` file, but it cannot reopen the contents of a directory such as `.env.d`.

## `net`

The `net` key controls outbound network access.

### Allow everything or nothing

```jsonc
{
  "sandbox": {
    "net": true
  }
}
```

```jsonc
{
  "sandbox": {
    "net": false
  }
}
```

Coarse allow-all and deny-all settings do not start a proxy. Adding `proxy` beside either boolean is an error.

Fine-grained host, CIDR, and private-network allows require a sibling proxy mode.

```jsonc
{
  "sandbox": {
    "net": ["api.example.com"],
    "proxy": "passthrough"
  }
}
```

Use `passthrough` to enforce connection-level rules without terminating TLS. The `auto` and `terminate` modes remain experimental and are part of the current decision audit.

### Allow specific hosts

```jsonc
{
  "sandbox": {
    "net": [
      "registry.npmjs.org",
      "api.github.com"
    ],
    "proxy": "passthrough"
  }
}
```

Anything not listed is denied.

### Allow a domain and its subdomains

A leading `*.` matches the named domain and subdomains at any depth.

```jsonc
{
  "sandbox": {
    "net": [
      "*.example.com"
    ],
    "proxy": "passthrough"
  }
}
```

This matches `example.com`, `api.example.com`, and `a.b.example.com`. It does not match `notexample.com` or `example.com.attacker.test`.

The only host wildcards are bare `*` and leading `*.`. Patterns such as `api.*.example.com` are errors.

### Allow an IP range

Use CIDR notation.

```jsonc
{
  "sandbox": {
    "net": [
      "203.0.113.0/24",
      "2001:db8::/32"
    ],
    "proxy": "passthrough"
  }
}
```

### Allow private networks

Private IPv4 and IPv6 ranges remain blocked unless the sandbox config names `<private>` or its `<local>` alias.

```jsonc
{
  "sandbox": {
    "net": [
      "<private>"
    ],
    "proxy": "passthrough"
  }
}
```

```jsonc
{
  "sandbox": {
    "net": [
      "api.example.com",
      "<local>"
    ],
    "proxy": "passthrough"
  }
}
```

### Deny a host

Prefix an array entry with `!`.

```jsonc
{
  "sandbox": {
    "net": [
      "*",
      "!*.tracking.example"
    ],
    "proxy": "passthrough"
  }
}
```

The last matching rule wins.

```jsonc
{
  "sandbox": {
    "net": [
      "*",
      "!api.example.com",
      "api.example.com"
    ],
    "proxy": "passthrough"
  }
}
```

The final rule re-allows `api.example.com`.

### Use the object form

```jsonc
{
  "sandbox": {
    "net": {
      "registry.npmjs.org": true,
      "*.tracking.example": false
    },
    "proxy": "passthrough"
  }
}
```

Object values carry engine-specific network rules. Network values do not accept filesystem modes such as `"r"` or `"rw"`.

### Keep inherited network settings

Use `"..."` in an array.

```jsonc
{
  "sandbox": {
    "net": [
      "...",
      "api.example.com"
    ],
    "proxy": "passthrough"
  }
}
```

At the outermost level, the inherited secure network settings allow no outbound connections.

## `env`

The `env` key controls the environment passed to the child process. The engine builds a new environment from the allowed entries.

### Pass everything or nothing

```jsonc
{
  "sandbox": {
    "env": true
  }
}
```

```jsonc
{
  "sandbox": {
    "env": false
  }
}
```

On POSIX systems, `false` passes no ambient variables. On Windows, the engine retains only the small set needed to start the child reliably.

### Pass selected variables

Array entries are optional. A missing variable does not cause an error.

```jsonc
{
  "sandbox": {
    "env": [
      "PATH",
      "HOME",
      "NODE_ENV",
      "VITE_*"
    ]
  }
}
```

### Strip selected variables

```jsonc
{
  "sandbox": {
    "env": [
      "*",
      "!*_TOKEN",
      "!*_SECRET",
      "!AWS_*"
    ]
  }
}
```

This denylist is convenient, but an explicit allowlist is safer because secret names vary.

```jsonc
{
  "sandbox": {
    "env": [
      "PATH",
      "HOME",
      "NODE_ENV"
    ]
  }
}
```

### Require a variable

Plain object keys are required.

```jsonc
{
  "sandbox": {
    "env": {
      "DATABASE_URL": true
    }
  }
}
```

Compilation fails when `DATABASE_URL` is absent.

### Make a variable optional

Add `?` to the key.

```jsonc
{
  "sandbox": {
    "env": {
      "LOG_LEVEL?": true
    }
  }
}
```

Glob keys are always optional.

```jsonc
{
  "sandbox": {
    "env": {
      "VITE_*": true
    }
  }
}
```

### Validate values

The string form accepts `string`, `integer`, `number`, `port`, a regular expression, or a literal union.

```jsonc
{
  "sandbox": {
    "env": {
      "NODE_ENV": "string",
      "WORKERS": "integer",
      "RATIO": "number",
      "PORT": "port",
      "REGION": "/^[a-z]{2}-[a-z]+-\\d$/",
      "LOG_LEVEL": "'debug'|'info'|'warn'|'error'"
    }
  }
}
```

A `number` value must be finite. A `port` value must be an integer from 1 through 65535.

### Mark a value as sensitive

Environment object entries are sensitive by default. Use `sensitive: false` only for a value that can be shown in logs and diagnostics.

```jsonc
{
  "sandbox": {
    "env": {
      "API_TOKEN": {
        "sensitive": true
      },
      "PUBLIC_ORIGIN": {
        "sensitive": false
      }
    }
  }
}
```

### Combine validation and options

```jsonc
{
  "sandbox": {
    "env": {
      "PORT": {
        "format": "port",
        "sensitive": false
      },
      "LOG_LEVEL": {
        "format": "'debug'|'info'|'warn'|'error'",
        "optional": true,
        "sensitive": false
      }
    }
  }
}
```

The extras object accepts `format`, `optional`, `sensitive`, and `value`.

### Set a literal value

```jsonc
{
  "sandbox": {
    "env": {
      "NODE_ENV": {
        "value": "production",
        "sensitive": false
      }
    }
  }
}
```

### Keep the safe inherited environment

Use `"..."` in an array.

```jsonc
{
  "sandbox": {
    "env": [
      "...",
      "NODE_ENV"
    ]
  }
}
```

Use `"..."`: `true` in the object form.

```jsonc
{
  "sandbox": {
    "env": {
      "...": true,
      "NODE_ENV": true,
      "AWS_*": false
    }
  }
}
```

At the outermost level, `"..."` inserts the curated, non-secret environment used by `sandbox: true`.

## Inheritance

A sandbox object is a complete statement. If it names only `fs`, the omitted `net` and `env` axes are denied.

```jsonc
{
  "sandbox": {
    "fs": ["./dist"]
  }
}
```

The sandbox config above means:

```jsonc
{
  "sandbox": {
    "fs": ["./dist"],
    "net": false,
    "env": false
  }
}
```

Use object-level `"..."`: `true` to keep every omitted axis from the enclosing sandbox config.

```jsonc
{
  "sandbox": {
    "...": true,
    "fs": ["...", "./dist"]
  }
}
```

> **Current bridge gap:** object-level `"..."` works in the sandbox compiler, but the project `nub.jsonc` parser does not accept it yet.

Within an axis array, `"..."` inserts that one inherited axis at its position.

```jsonc
{
  "sandbox": {
    "fs": ["...", "./dist"],
    "net": ["...", "api.example.com"],
    "proxy": "passthrough",
    "env": ["...", "NODE_ENV"]
  }
}
```

Order still matters after inheritance.

```jsonc
{
  "sandbox": {
    "env": [
      "...",
      "!AWS_*",
      "AWS_REGION"
    ]
  }
}
```

The example inherits the safe environment, strips every `AWS_*` value, then re-allows `AWS_REGION`.

## Complete examples

### Build without network access

```jsonc title="sandbox configuration"
{
  "sandbox": {
    "fs": {
      "./src": "r",
      "./package.json": "r",
      "./dist": "rw",
      "<tmp>": "rw"
    },
    "net": false,
    "env": {
      "PATH": true,
      "NODE_ENV?": "'development'|'production'",
      "CI?": "string"
    }
  }
}
```

### Development server

```jsonc title="sandbox configuration"
{
  "sandbox": {
    "fs": {
      "./": "r",
      "./.next": "rw",
      "<cache>": "rw",
      "<tmp>": "rw"
    },
    "net": [
      "api.example.com",
      "*.sentry.io"
    ],
    "proxy": "passthrough",
    "env": {
      "...": true,
      "NODE_ENV": "'development'",
      "PORT?": "port",
      "DATABASE_URL": true
    }
  }
}
```
